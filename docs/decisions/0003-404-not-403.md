# ADR-0003: Ownership violations answer 404, never 403

- **Status:** accepted
- **Date:** Step 5 (sessions), generalized Step 7
- **Context:** Multi-tenant endpoints must refuse cross-user access. 403
  ("forbidden") is the semantically obvious code — and it confirms the
  resource EXISTS, which is itself a leak about another person's data.
- **Decision:** We will make wrong-owner and nonexistent
  indistinguishable from outside: one `get_owned_candidate` check, one
  404 answer, applied by every candidate-scoped endpoint; the hostile
  suite enforces it across the whole attack surface, and the
  guard-that-guards-the-guard keeps the attack surface list honest.
- **Consequences:** Easier: nothing to probe; one function to audit.
  Harder: debugging a legitimate wrong-id bug looks identical to a
  security refusal — the operator must check the database, not the
  status code. Accepted: operators have the database; attackers don't.
